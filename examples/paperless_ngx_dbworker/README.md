# Native Paperless-ngx ingestion variation

The benchmark now submits the original folder-consumption producer, `documents.management.commands.document_consumer._consume_file`, on both arms. The Celery arm starts the pristine `paperless.celery:app` and publishes the original `documents.tasks.consume_file` task. It retains signed-pickle task/result serialization, the Redis result backend, task tracking, hard timeout and `worker_max_tasks_per_child=1`. It defines no replacement Celery task and does not invoke the task body directly in that arm. A live origin check verifies the registered task body against the pinned checkout before submission.

The DBWorker variation replaces only queue publication with one persistent `Job` per original task. It executes the original business body with task identity and reuses upstream publication/prerun/postrun/failure state helpers to maintain actual `PaperlessTask` application records. The original producer, preflight, ASN, collation, barcode, workflow, parser/OCR, metadata, file and search signal code remain unchanged. The persisted object payload is trusted local benchmark data; its pickle storage is not an untrusted public interface.

Conditional barcode child consumption, deferred indexing, AI indexing and webhook task publication are mapped to independent durable jobs with parent identities and availability times. No child business task is executed inline or discarded. Unknown tasks, eager Celery execution and unsupported canvas continuations raise errors. Automatic retry behavior for those additional stages is not admitted; the selected successful fixture allows exactly one unsplit ingestion stage per scan and fails graph admission if a conditional continuation occurs. Normal successful search indexing is synchronous upstream work and is not invented as another queue job.

The declared fixture uses raster-only PNG scans with real Tesseract OCR, English, forced OCR, PDF output, no cleaning/rotation/deskew, two worker slots and one OCR thread. It has no configured workflows, matching tags, AI index or barcode split. Two warm-up scans are recorded separately. Redis remains an auxiliary cache/progress channel for both stacks; the native Celery arm also uses its actual broker and result backend.

Timing begins with the first original producer call and ends only when every required job has a terminal success event, a durable native-equivalent task record and result, a completed DBWorker ledger when applicable, and search-ready business output. Original/thumbnail/archive hashing and full independent output checks run after timing. Validation includes OCR markers, original SHA256, real rendered thumbnail, PDF archive text/page count, document metadata, task timestamps, trigger source and task result relationships. An append-only trace is replayed to verify input identities, single-attempt counts, parent/child edges and quiescence for the restricted graph. Failed, duplicate, extra, missing or uncorrelated task work is rejected.

Native tracking exceptions are fatal even when Celery reports task success. The harness rejects upstream lifecycle error messages in the worker log and allows only 30 seconds for original postrun tracking after every trace and Redis result becomes terminal. Missing tracking records fail admission; the harness never repairs them or derives lifecycle success from business output. SQLite lock failures must be resolved through the runner or an explicitly declared, equally configured application database before rerunning.

Owned-stack metrics sample harness, Redis, native worker replacements or DBWorker processes, and OCR descendants every 50ms. Very short processes can be missed between samples; this limitation is recorded. Native Celery recycles children after each task, while DBWorker currently uses persistent spawn workers. The suite declares that difference and does not claim timeout, cancellation, retry, worker-crash or cross-ORM transaction parity.

Native prefork parser admission requires Linux. The previous macOS thread-pool diagnostic is not an acceptable replacement for the original worker lifecycle, and the migrated Celery arm fails explicitly on macOS. Restricted execution contexts can also block local listening sockets and process resource observation. No migrated end-to-end native result is claimed without a successful run on a suitable runner.

Provision Python 3.12 environments from `benchmarks/locks/paperless_ngx.txt`, install the root DBWorker project, and expose the pristine source through `PYTHONPATH`. Native tools: Redis, Tesseract English/OSD data, Ghostscript, ImageMagick, Poppler, libmagic and qpdf. Unused lazy AI embedding providers, sentence-transformers and torch are outside this restricted installation.

Offline tests in `benchmarks/tests/test_paperless_native.py` exercise the real native source check and signed serializer, original producer, persistent job granularity, delayed child publication and original control-state helpers. They also execute the unchanged ingestion body in-process with real OCR, thumbnails, archive and search validation. These tests use real local-memory Django cache and channel backends for service isolation; they do not start a Celery worker, fabricate DBWorker ledger completion or produce a successful performance report. The benchmark itself retains real Redis.
